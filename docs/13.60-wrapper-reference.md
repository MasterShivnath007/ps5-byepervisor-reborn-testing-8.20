# 13.60 wrapper reference and 8.20 AP path

**Summary:** Hypercall wrapper ABI, 8.20 offset provenance, and the AP payload
entry shape.

## 13.60 wrappers

`hc 0x0F` at file offset `0xC16EE0`:

```text
push rbp
mov rsp, rbp
push rbx
mov rdx, rbx      ; RBX = incoming RDX (CR3)
mov rsi, rcx      ; RCX = incoming RSI (carrier / start RIP)
mov eax, 0xf
mov edx, edi      ; RDX = incoming EDI (core / APIC id)
vmmcall
pop rbx
pop rbp
ret
```

`hc 0x10` at `0xC16F00`:

```text
push rbp
mov rsp, rbp
mov eax, 0x10
vmmcall
pop rbp
ret
```

The hc `0x0F` wrapper shuffles `(core, start_rip, cr3)` into the vmmcall
registers `(RDX, RCX, RBX)`. The hc `0x10` wrapper takes no arguments.

## 13.60 ACPI sleep function

The 13.60 Reborn table gives:

```text
KERNEL_SYM_ACPI_SLEEP_MACHDEP_HOOK = 0x3913B0
KERNEL_SYM_HV_MP_STARTUP_CALL      = 0xC16EE0
```

Disassembly of `0x3913B0`:

- loops over CPUs starting at index 1;
- calls `acpi_wakeup_cpu` at `0x391780` with `RDI=wake state`, `ESI=cpu`;
- calls the hc `0x10` wrapper at `0x39144F`;
- has an hc `0x0F` call site at `0x391809`.

The writeup's `acpi_sleep_machdep+0x18e` is **not confirmed**:
`0x3913B0 + 0x18E = 0x39153E` lands in the middle of an instruction. Treat it
as unverified.

The working 13.60 Reborn source hooks `HV_MP_STARTUP_CALL` (`0xC16EE0`) and
sets `RSI=payload`, `RDX=CR3`, preserving `RDI`. It writes the payload and
params in the hook chain, not at arm time.

## 8.20 offsets

```text
HV_MP_STARTUP_CALL        = 0xBC40F0   ; hc 0x10 wrapper, not hc 0x0F
MP_STARTUP_INIT_VECTOR    = 0x2A5E28
ACPI_SLEEP_MACHDEP_HOOK   = 0x00000000 ; missing
```

Candidate hc `0x0F`: `0xBC40D0` (13.60 layout places hc `0x0F` `0x20` before hc
`0x10`). Candidate hc `0x10`: `0xBC4110`. Both are unverified.

## 8.20 reference loader

The 8.20 reference loader contains `0xBC40F0` and `0x2A5E28`, does not contain
`0xBC4110` or `0x3913B0`, preserves `RDI`, and writes the payload/params in the
hook chain. Its AP payload is the older 11.60 scanner, not the Reborn payload.
The `RDI` override is therefore not the root cause.

## AP payload entry

The 8.20 Reborn entry matches the 13.60 strategy:

```text
lea rsp, [rip + 0xef9]      ; rsp = page + 0xF00
push rbx
push rsi
push rdi
sub rsp, 8
lea rbx, [rsp + 0x20]       ; params at page + 0xF00
mov rdi, rbx
call vmcb_disable_np
mov rcx, [rbx]              ; init_cb = param[0]
add rsp, 8
pop rdi
pop rsi
pop rbx
jmp rcx
```

The payload layout, stack and params are not the problem.

## Missing pieces

1. 8.20 bytes at `0xBC40F0` and `0xBC4110` to confirm the wrapper ABI.
2. The 8.20 ACPI sleep function and its hc `0x10` call site.
3. 8.20 bytes at `0x2A5E28` (stock MP startup vector).
4. The 8.20 AP-start call sites and argument setup.
5. AP entry stack/carrier expectations and whether the kernel reuses or zeroes
   `0x3FFFF000` during suspend.
